# Phase 02: Migration Consolidation

## Purpose

Collapse 16 iterative Alembic migration files into a single initial migration that reflects the current schema. The project is pre-production — old migration history only reflects development churn, not real data evolution. No schema changes are introduced; this is purely a cleanup of migration artifacts.

## Context

The `alembic/versions/` directory contains 16 migration files created during development. The base migration (`7130ecb0388c_true_initial_migration.py`) creates most tables but is missing several elements added by subsequent migrations. The consolidation must produce one file that creates the entire schema correctly from scratch.

**Locked decisions (from phase discuss):**
- Consolidate all 16 files into exactly 1 migration file
- No intermediate steps kept; all old files deleted
- Fresh revision ID generated via `alembic revision`
- Downgrade drops all tables, enums, and constraints
- Validation: drop DB, run `alembic upgrade head`, verify schema

**Elements missing from base migration that must be folded in:**
1. `registration_requests` table + `registration_status` ENUM
2. `updated_at` columns on `users` and `layouts` tables
3. Column types changed from TEXT to VARCHAR(255) for 8 columns across 6 tables
4. `update_updated_at_column()` trigger function + 5 triggers
5. `users_email_length_check` CHECK constraint
6. Expression unique index `uq_aggregated_data_dashboard_graph_dims` for UPSERT
7. Composite index `idx_aggregated_data_dashboard_graph`
8. Index `idx_processing_logs_dashboard_id`
9. `users.role` DEFAULT `'viewer'::user_role`
10. `dashboards.config` JSONB column

## Tasks

<task id="01" name="Generate new Alembic revision file">
Run `alembic revision -m "initial_consolidated"` to generate a new migration file with a proper revision ID and timestamp. This creates the file stub in `alembic/versions/` with the correct Alembic header format from `script.py.mako`.

The auto-generated file will have the standard imports (`from alembic import op`, `import sqlalchemy as sa`) and empty `upgrade()`/`downgrade()` functions. These will be replaced entirely in the next task.

Note: The revision ID is auto-generated by Alembic. Do NOT manually specify it.
</task>

<task id="02" name="Write consolidated upgrade() function">
Replace the auto-generated `upgrade()` function in the new migration file with the complete schema creation logic. The function must create all database objects in dependency order:

**Operation ordering:**
1. Create all 6 PostgreSQL ENUM types using `postgresql.ENUM.create(checkfirst=True)`:
   - `user_role`: admin, editor, viewer
   - `dashboard_permission_level`: view, edit, admin
   - `graph_type`: bar, line, pie, table
   - `filter_type`: select, multiselect, range, date
   - `processing_status`: started, uploaded, processing, success, failed, completed
   - `registration_status`: pending, approved, rejected

2. Create tables without FK dependencies first (using `CREATE TABLE IF NOT EXISTS`):
   - `users` — with `VARCHAR(255)` for email/password_hash, `updated_at` column, `DEFAULT 'viewer'::user_role` on role
   - `layouts` — with `VARCHAR(255)` for name, `updated_at` column
   - `filters` — with `VARCHAR(255)` for name

3. Create tables with FK dependencies:
   - `dashboards` — with `VARCHAR(255)` for name, `config` JSONB column, `updated_at` column
   - `graphs` — with `VARCHAR(255)` for name, `updated_at` column
   - `dashboard_access` — composite PK
   - `dashboard_filters` — composite PK
   - `processing_configs` — with `updated_at` column
   - `processing_logs` — with `VARCHAR(1000)` for message
   - `aggregated_data` — BIGSERIAL PK
   - `registration_requests` — with `VARCHAR(255)` for email, `INET` for IP

4. Create all indexes (using `CREATE INDEX IF NOT EXISTS`):
   - Unique indexes: `idx_users_email`, `idx_layouts_name`, `idx_dashboards_name`, `idx_graphs_dashboard_name`, `idx_filters_name`
   - B-tree indexes: `idx_users_role`, `idx_graphs_dashboard`, `idx_aggregated_data_dashboard_id`, `idx_aggregated_data_graph_id`, `idx_dashboard_access_user`, `idx_dashboard_access_dashboard`, `idx_dashboard_filters_dashboard_filter`, `idx_processing_logs_dashboard_id`
   - Composite B-tree: `idx_aggregated_data_dashboard_graph`
   - GIN: `idx_aggregated_data_dims_gin`
   - Expression unique: `uq_aggregated_data_dashboard_graph_dims` on `(dashboard_id, graph_id, (dims::text))`

5. Add CHECK constraint: `users_email_length_check` via `DO $$` guard block

6. Create trigger function: `update_updated_at_column()` via `CREATE OR REPLACE FUNCTION`

7. Create 5 triggers via `DO $$` guard blocks:
   - `update_dashboards_updated_at` ON dashboards
   - `update_processing_configs_updated_at` ON processing_configs
   - `update_layouts_updated_at` ON layouts
   - `update_graphs_updated_at` ON graphs
   - `update_users_updated_at` ON users

**Column type requirements (VARCHAR(255) instead of TEXT):**
- `users.email` → `VARCHAR(255)`
- `users.password_hash` → `VARCHAR(255)`
- `layouts.name` → `VARCHAR(255)`
- `dashboards.name` → `VARCHAR(255)`
- `graphs.name` → `VARCHAR(255)`
- `filters.name` → `VARCHAR(255)`
- `processing_logs.message` → `VARCHAR(1000)`
- `registration_requests.email` → `VARCHAR(255)`

**Key patterns to follow:**
- All raw SQL via `op.execute()` with `IF NOT EXISTS` / `IF EXISTS` guards
- ENUM creation via `postgresql.ENUM.create(op.get_bind(), checkfirst=True)`
- Trigger function via `CREATE OR REPLACE FUNCTION`
- Triggers and CHECK constraints via `DO $$` guard blocks (check `pg_trigger` / `pg_constraint`)
- Follow exact patterns from `7130ecb0388c_true_initial_migration.py` and `ce58bba5d461_add_db_constraints_and_fix_schema_issues.py`
</task>

<task id="03" name="Write consolidated downgrade() function">
Replace the auto-generated `downgrade()` function with complete teardown logic:

**Downgrade ordering:**
1. Drop all 5 triggers (use `DROP TRIGGER IF EXISTS`):
   - `update_dashboards_updated_at` ON dashboards
   - `update_processing_configs_updated_at` ON processing_configs
   - `update_layouts_updated_at` ON layouts
   - `update_graphs_updated_at` ON graphs
   - `update_users_updated_at` ON users

2. Drop trigger function: `DROP FUNCTION IF EXISTS update_updated_at_column()`

3. Drop tables in reverse dependency order (use `DROP TABLE IF EXISTS CASCADE`):
   - `dashboard_access`
   - `dashboard_filters`
   - `filters`
   - `graphs`
   - `aggregated_data`
   - `processing_configs`
   - `processing_logs`
   - `registration_requests`
   - `dashboards`
   - `layouts`
   - `users`

4. Drop all 6 ENUM types using `postgresql.ENUM.drop(op.get_bind(), checkfirst=True)`:
   - `user_role`
   - `dashboard_permission_level`
   - `graph_type`
   - `filter_type`
   - `processing_status`
   - `registration_status`
</task>

<task id="04" name="Validate consolidated migration against database">
Drop the existing database (or use a fresh test database) and run the consolidated migration from scratch:

1. Drop and recreate the database:
   ```
   psql -h localhost -p 5432 -U postgres -c "DROP DATABASE IF EXISTS bidb;"
   psql -h localhost -p 5432 -U postgres -c "CREATE DATABASE bidb;"
   ```

2. Run the consolidated migration:
   ```
   uv run alembic upgrade head
   ```

3. Verify the schema matches expectations:
   - All 10 tables exist: `users`, `layouts`, `dashboards`, `graphs`, `filters`, `dashboard_access`, `dashboard_filters`, `processing_configs`, `processing_logs`, `aggregated_data`, `registration_requests`
   - All 6 ENUM types exist
   - All 19 indexes exist (check via `\d <table>` for each table)
   - Trigger function exists (check via `\df`)
   - All 5 triggers exist (check via `\d <table>` for each table with `updated_at`)
   - CHECK constraint `users_email_length_check` exists
   - Column types are correct (VARCHAR(255) not TEXT for the 8 columns listed above)
   - `dashboards.config` column exists
   - `users.role` has DEFAULT `'viewer'::user_role`

4. Verify downgrade works:
   ```
   uv run alembic downgrade base
   ```
   All tables, enums, triggers, and the trigger function should be dropped cleanly.

5. Re-run upgrade to leave DB in clean state:
   ```
   uv run alembic upgrade head
   ```
</task>

## Risk Assessment
