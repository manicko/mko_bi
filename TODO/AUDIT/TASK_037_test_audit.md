# Задача

## 1) Выявить плохие тесты

Признаки плохих тестов:
- не отвечают паттерну тех задания (pandas вместо polars)
- Не проверяют бизнес-логику (только создание объектов или успешные коды ответов).
- Игнорируют негативные сценарии и граничные условия.
- Используют минимальные данные вместо реалистичных.
- Не проверяют состояние базы данных или логов после выполнения.
- Имеют низкую диагностическую ценность.
- Проверяют вызов метода, но не бизнес-правила.
- Являются примитивными заглушками вместо использования данных, близких к реальным.
- избыточные
- дублирующие 
- поверхностные (не затрагивают суть);
- пустые и формальные тесты (типа «поле существует», функция есть, без проверки поведения);
- mock полностью заменяет бизнес-логику
- assertions проверяют значения из mock
- тест не проверяет реальное поведение

Особое внимание обращать на:
- Тесты, которые используют `pytest` без `assert` или с `assert True`.
- Моки, используемые вместо реальных зависимостей там, где это не обязательно (например, мок репозитория внутри сервиса, когда можно использовать тестовую БД).
- Тесты, которые зависят от конкретного порядка выполнения и не изолированы.
