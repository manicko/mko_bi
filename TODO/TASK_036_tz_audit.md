## 2. Архитектурные проблемы

### Critical

1. **Неработоспособность тестов из-за ошибок импорта**
   - Файл: `interfaces/service_interfaces.py:12`
   - Проблема: Импортируется `from mko_bi.models.graph import GraphRead`, но:
     - Модуля `mko_bi.models.graph` не существует (есть только `dashboard.py`, `filters.py` и т.д.)
     - Правильный путь: `mko_bi.db.models.graphs` (множественное число)
     - Класс `GraphRead` вообще не определен ни в одном месте
   - Влияние: 9 тестовых файлов не могут выполниться (337 тестов заблокированы)
   - Решение: Создать Pydantic модели `GraphRead`, `GraphCreate`, `GraphUpdate` в `models/` и исправить импорты в `service_interfaces.py`

2. **Смешение слоев: API напрямую использует SQLAlchemy модели**
   - Файлы: `services/data_service.py:453-459`, `services/data_service.py:797-800`
   - Проблема: Сервисы и API используют SQLAlchemy модели (`db.models.graphs.Graph`) вместо Pydantic
   - Нарушает принцип разделения слоев (Clean Architecture)
   - Решение: Использовать Pydantic модели для передачи данных между слоями

### High

3. **Дублирование деклараций интерфейсов**
   - Файлы: `interfaces/repository_interfaces.py`, `interfaces/service_interfaces.py` и дубликаты в `interfaces_old/`
   - Проблема: Существуют две версии интерфейсов, но используются неконсистентно
   - Решение: Удалить `interfaces_old/`, оставить одну версию интерфейсов

4. **Отсутствие реализации сервисов для графиков**
   - Файл: `interfaces/service_interfaces.py:110-142` (интерфейс `IGraphService`)
   - Проблема: Интерфейс определен, но нет реализации в `services/`
   - Решение: Создать `GraphService` в `services/graph_service.py`

### Medium

5. **Dead code: неиспользуемые файлы**
   - `data/processing/base.py` - абстрактный класс `DataProcessor`, но не используется (вместо него используются функции в `transformations.py`)
   - `dashboards/base.py` - базовый класс есть, но реализации в `implementations/` используют заглушки
   - Решение: Либо удалить, либо интегрировать в работающую систему

6. **Использование `get_session()` внутри сервисов приводит к проблемам с транзакциями**
   - Файл: `services/data_service.py` - множественные вызовы `get_session()` внутри одной операции
   - Проблема: Создается несколько независимых сессий
   - Решение: Передавать сессию как параметр через все уровни

## 3. Проблемы в коде

### Critical

1. **Исключения без контекста (breadcrumbs)**
   - Файлы: Множество мест
   - Пример: `core/permissions.py:105` - `raise ValueError(f"Неизвестная роль: '{role}'")` без `from e`
   - Ruff подсвечивает: `B904 Within an except clause, raise exceptions with 'raise ... from err'`
   - Решение: Использовать `raise ... from e` для сохранения цепочки исключений

2. **Импорты не в начале файла**
   - Файл: `core/permissions.py:43-44`
   - Ruff ошибка: `E402 Module level import not at top of file`
   - Проблема: Импорты после кода функции
   - Решение: Перенести все импорты в начало файла

3. **Некорректное использование `typing`**
   - Файл: `utils/decorators.py:20`
   - Ruff ошибка: `UP047 Generic function 'timing' should use type parameters`
   - Решение: Использовать правильный синтакс generics

### High

4. **Hardcoded demo data вместо реальной интеграции**
   - Файл: `dashboards/implementations/dashboard_1.py:137-144`
   - Проблема: Дашборды возвращают `sample_data` вместо запросов к API/БД
   - Решение: Интегрировать с `DataService` или API вызовы

5. **Отсутствие обработки ошибок при удалении файлов**
   - Файл: `services/data_service.py:1109-1130` (`cleanup_task_files`)
   - Проблема: Исключения логируются, но не обрабатываются (файлы могут накапливаться)
   - Решение: Добавить обработку и возможно cron-задачу для очистки

6. **Использование `any` вместо `Any`**
   - Файл: `services/auth_service.py:29` - `-> dict[str, any]`
   - Проблема: `any` - это встроенная функция, а не тип
   - Решение: Использовать `Any` из `typing`

## 4. Проблемы безопасности

### High

1. **Rate limiting хранится в памяти**
   - Файлы: `api/routes/auth.py:36`, `services/auth_service.py:110`
   - Проблема: `_login_attempts` - обычный словарь в памяти. При перезапуске данные теряются, в multi-worker окружении не работает
   - Решение: Использовать Redis или аналогичное внешнее хранилище

2. **Отсутствие ограничения размера загружаемых файлов в Polars**
   - Файл: `services/data_service.py:132` - `pl.read_csv(file_path)`
   - Проблема: Огромный CSV файл может исчерпать память
   - Решение: Проверять размер ДО чтения, использовать chunked чтение для больших файлов

3. **SQL-инъекции маловероятны, но...**
   - Файлы: Множество мест где используется SQLAlchemy Core (не ORM стиль)
   - Текущая реализация использует параметризованные запросы, но в `apply_data_filters` динамическое построение условий может быть уязвимым
   - Решение: Проверить все динамические фильтры

### Medium

4. **JWT токены не имеют механизма отзыва**
   - Файл: `core/security.py`
   - Проблема: После logout токен остается валидным до истечения срока
   - Решение: Реализовать Redis blacklist или аналогичный механизм

5. **Пароли обрезаются до 72 байт**
   - Файл: `core/security.py:20-41` - `_truncate_password()`
   - Проблема: Если пароль длиннее 72 байт (многобайтовые символы), он обрезается
   - Решение: Использовать pre-hash (SHA256) перед bcrypt, как рекомендуется

6. **CORS настроен на `allow_origins=["*"]`**
   - Файл: `app.py:44-50`
   - Проблема: В production нельзя разрешать все домены
   - Решение: Указать конкретные домены в конфигурации

## 5. Проблемы данных

### Critical

1. **YoY расчет некорректен**
   - Файл: `data/processing/transformations.py:262-293` - `_calculate_yoy()`
   - Проблема: Просто делает `shift(1)` без группировки по категориям/измерениям
   - Пример: Если данные: `[{"year": 2023, "cat": "A"}, {"year": 2023, "cat": "B"}, {"year": 2024, "cat": "A"}]`
   - Текущий код сравнит 2024-A с 2023-B (неверно!)
   - Решение: Группировать по dims перед расчетом YoY

2. **Идемпотентность пересчета не гарантирована**
   - Файл: `services/data_service.py:499-506`
   - Проблема: `clear_old=True` удаляет старые данные, но если вставка новых падает, данных нет вообще
   - Решение: Использовать транзакции правильно (уже есть `with save_db.begin()`, но проверить)

### Medium

3. **Обработка пустых CSV / битых строк**
   - Файл: `data/processing/base.py:50-67` - `_validate_input()`
   - Проблема: Проверяет только пустые данные, но не битые строки
   - Решение: Добавить обработку ошибок парсинга в `pl.read_csv()`

4. **Соответствие graphs ↔ aggregated_data**
   - Файл: `services/data_service.py:470-496`
   - Проблема: Создает агрегаты на основе `preview` (первые 10 строк), а не всех данных
   - Решение: Использовать полный результат обработки
