# TASK_033: Полный аудит BI системы на соответствие SPEC и production-ready

## Цель

Провести **комплексный аудит проекта**, чтобы определить:

1. Полностью ли реализовано ТЗ (`SPEC.md`)
2. Корректно ли работает система end-to-end
3. Есть ли архитектурные и кодовые проблемы
4. Безопасна ли система
5. Готов ли проект к использованию и деплою

---

## Область аудита

Аудит включает:

* код
* архитектуру
* данные
* API
* UI (Dash)
* инфраструктуру
* безопасность
* пользовательские сценарии

---

## 1. Проверка полноты реализации SPEC.md

Для каждого требования:

* ✅ реализовано полностью
* ⚠️ частично
* ❌ отсутствует

Проверить:

* Upload CSV / CSV.gz (включая удаление файлов)
* Обработка через Polars (groupby, YoY, доли, кастомные метрики)
* PostgreSQL (все таблицы из SPEC)
* JWT + bcrypt (все endpoints защищены)
* RBAC (admin/editor/viewer)
* Dash + Plotly (все типы графиков)
* Filters (глобальные, backend-driven)
* Logging (upload, processing, errors, access)

---

## 2. End-to-End сценарии (обязательно)

Проверить реальные пользовательские флоу:

### Сценарий 1: Admin

* создаёт dashboard
* настраивает графики
* выдаёт доступ

### Сценарий 2: Editor

* загружает CSV
* запускает processing
* данные появляются

### Сценарий 3: Viewer

* логинится
* видит только доступные dashboards
* применяет фильтры

Проверить:

* ошибки
* пустые состояния
* некорректные данные

---

## 3. Data correctness

Проверить:

* корректность агрегаций (groupby, YoY, доли)
* обработку:

  * пустых CSV
  * битых строк
  * неверных типов
* идемпотентность пересчёта
* отсутствие дублирования данных
* соответствие graphs ↔ aggregated_data

---

## 4. Архитектурный аудит

Проверить:

* смешение слоёв (API / service / repository)
* циклические зависимости
* нарушение Dependency Inversion
* прямой доступ к БД из API
* глобальные состояния
* отсутствие интерфейсов
* dead code
* пустые файлы
* дублирующийся код

---

## 5. Аудит кода

Проверить:

### Ошибки

* `except: pass`
* отсутствие логирования
* неправильные HTTP коды

### Транзакции

* commit / rollback
* конкурентный доступ

### Файлы

* пустые файлы
* дублирующийся код
* удаление временных файлов

### Конфигурация

* хардкод
* отсутствие env

### Типизация

* mypy
* ruff
* Any / Optional

---

## 6. Безопасность (расширенная)

Проверить:

* JWT expiration / refresh
* защита всех endpoints
* RBAC enforcement
* password policy
* brute-force защита
* rate limiting
* upload:

  * размер файла
  * mime type
  * path traversal
* SQL injection
* безопасная работа с CSV
