## 1. Executive Summary

Проект mko_bi — BI система на базе FastAPI + Dash + PostgreSQL. Архитектура соответствует Clean Architecture с разделением на слои API → Services → Repositories → DB.

**Текущий статус:** ~70% готовности (архитектурная основа готова, требуется исправление критических ошибок и завершение интеграции)

**Версия Python:** 3.12  
**Основной стек:** FastAPI, Dash, Polars, SQLAlchemy (asyncpg), PostgreSQL

## 5. Последовательный план разработки

### Этап 1: Критические архитектурные исправления

**Цель:** Устранить риски deadlock, race conditions, некорректной работы с БД

1. **TASK-001** — Унификация sync/async кода
   - Перевод `data_service.py` на `AsyncSession`
   - Исправление всех импортов `from sqlalchemy.orm import Session`
   - Обновление вызовов в `upload.py`

2. **TASK-002** — Добавление транзакций
   - Оборачивание операций сохранения в `async with db.begin():`
   - Обработка rollback при ошибках

### Этап 2: Безопасность

**Цель:** Соответствие SPEC.md п.6

3. **TASK-003** — MIME-type валидация
   - Добавление проверки `file.content_type` в `data_service.py`
   - Опционально: использование `python-magic` для проверки magic numbers

4. **TASK-004** — Rate limiting для upload
   - Использование `fastapi-limiter` с Redis
   - Применение к endpoint-ам `/upload/*`

### Этап 3: Интеграция Dash

**Цель:** Работающие дашборды с реальными данными

5. **TASK-005** — Подключение Dash к FastAPI
   - Mount `dash_app` в `app.py`
   - Настройка совместного использования сессий БД

6. **TASK-006** — Аутентификация в Dash
   - Middleware для проверки JWT токенов
   - Перенаправление на логин при истечении токена

7. **TASK-007** — Реальные данные в графиках (цепочка)
   - Интеграция с API для получения данных
   - Замена заглушек в `_create_bar_chart`, `_create_line_chart` и др.
   - Реализация работающих фильтров (убрать `PreventUpdate`)

### Этап 4: Обработка данных

**Цель:** Полноценный pipeline с использованием готовых функций

8. **TASK-008** — Интеграция transformations.py в pipeline (цепочка)
   - Использование `calculate_aggregations()` вместо упрощенных функций
   - Связка `data_service.py` с `transformations.py`
   - Удаление дублирующихся функций (`_apply_aggregations`, `_apply_filters`)

9. **TASK-009** — Использование CSVLoader
   - Рефакторинг `data_service.py` для использования `CSVLoader` из `loaders/loader.py`
   - Удаление дублированных `_read_csv_safe`, `_validate_file_size`

### Этап 5: Качество кода

**Цель:** Удаление мертвого кода, исправление типов

10. **TASK-010** — Чистка мертвого кода (цепочка)
    - Удаление дублирования строк 464-476 в `data_service.py`
    - Удаление `pass` в строке 380 `_process_csv_file`
    - Исправление типа `dashboard_id` (int → UUID)

11. **TASK-011** — Гарантированное удаление файлов
    - Улучшение `finally` блока
    - Обработка `KeyboardInterrupt`

### Этап 6: Дополнительные фичи (опционально)

12. **TASK-012** — Multi-axis графики
    - Конфигурация `secondary_y`
    - Реализация в `dashboards/components/charts/`

13. **TASK-013** — Layouts (UI композиция)
    - Интеграция таблицы `layouts` с Dash

1. **Критически:** Исправление sync/async смешения
